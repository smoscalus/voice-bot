# Архитектура голосового бота «Сёма»

## 1. Цель

Бот сидит в голосовом канале Discord и:

1. **Прямое обращение** — отвечает, когда слышит своё имя («Сёма», «Бот», «ГПТ»…).
2. **Контекстная инициатива** — фоном слушает разговор и вклинивается *редко*, только когда
   обсуждают его темы (программирование, игры, музыка, споры) или явно ждут его мнения.

Главные ограничения: стоимость API и то, насколько бот раздражает людей. Отсюда принцип:
**сначала дешёвая проверка, потом дорогая**. Каждый следующий шаг вызывается реже предыдущего.

```
каждые 20 мс   VAD (локально, бесплатно)            — отсекает тишину
каждая фраза   STT                                  — главная статья расходов в фоне
каждая фраза   wake word + префильтр (regex/fuzzy) — бесплатно
редко          LLM-классификатор (JSON)             — только если префильтр набрал порог
очень редко    LLM-ответ + TTS                      — только после решения «говорить»
```

## 2. Почему не Realtime API как основной путь

| | Realtime API | STT → LLM → TTS (выбрано) |
|---|---|---|
| Несколько говорящих | Один входной аудиопоток: нужно микшировать, кто говорит — теряется | Discord отдаёт поток каждого отдельно, имя известно |
| Контроль «когда говорить» | Серверный VAD склонен отвечать на всё; приходится отключать и управлять вручную | Решаем сами, на любом шаге |
| Стоимость фонового прослушивания | Аудио-токены на вход за всё время | Дешёвый STT или локальный Whisper бесплатно |
| Задержка ответа | Минимальная (~0.5–1 с) | ~1.5–3 с (можно сократить, см. §8) |

Realtime имеет смысл как **замена связки «LLM + TTS» на этапе ответа**: отправляем в сессию
расшифровку текстом и получаем потоковый голос. Это кандидат на оптимизацию задержки, а не
основа архитектуры.

## 3. Компоненты

```
bot/
  main.py              Discord-клиент, слеш-команды /join /leave /proactive
  config.py            настройки из .env
  persona.py           имя, wake words, темы, системный промпт — «душа» бота
  session.py           VoiceSession: оркестратор одного канала
  audio/
    receiver.py        AudioSink для discord-ext-voice-recv → сегментатор
    segmenter.py       VAD-нарезка на фразы по каждому пользователю
    convert.py         48k stereo ↔ 16k mono ↔ 24k mono, WAV
    player.py          потоковый AudioSource для воспроизведения TTS
  stt/                 OpenAI (gpt-4o-mini-transcribe) или локальный faster-whisper
  tts/openai_tts.py    потоковый TTS в PCM
  brain/
    transcript.py      скользящий текстовый буфер
    triggers.py        wake word, стоп-слова, префильтр интересности
    interest.py        LLM-классификатор «вмешаться?»
    policy.py          кулдауны, лимиты, окна внимания
    responder.py       генерация реплики
```

## 4. Приём аудио от нескольких участников

- `discord.py` сам по себе голос **не принимает**. Используем расширение
  **discord-ext-voice-recv**: `channel.connect(cls=voice_recv.VoiceRecvClient)` + `vc.listen(sink)`.
  Альтернатива — форк **py-cord** со встроенной записью (`vc.start_recording`), но там
  запись отдаётся целиком по окончании, что хуже для реального времени.
- `AudioSink.write(user, data)` вызывается **из отдельного потока** на каждый 20-мс пакет
  каждого говорящего; `data.pcm` — PCM s16le 48 кГц стерео (3840 байт).
- На каждого пользователя — свой `webrtcvad.Vad` и свой буфер. Фраза начинается на первом
  речевом кадре (с 300 мс pre-roll, чтобы не съедать начало слова), заканчивается после
  `SILENCE_MS` тишины или при достижении `MAX_UTTERANCE_S`.
- **Ловушка:** когда человек молчит, Discord *перестаёт слать пакеты*. Поэтому конец фразы
  ловит ещё и таймер `flush_stale()` (каждые 100 мс из event loop).
- Фразы короче `MIN_UTTERANCE_MS` речи (кашель, щелчки) выбрасываются до STT — экономия.
- Передача в asyncio — только через `loop.call_soon_threadsafe(queue.put_nowait, utt)`.
- STT-запросы идут параллельно (семафор на 4), поэтому реплики в буфер вставляются
  отсортированными по времени **начала** фразы.
- Перед STT: стерео → моно, 48 → 16 кГц, WAV в памяти. Подсказка `prompt` с именем бота
  заметно улучшает распознавание wake word.
- Фильтр галлюцинаций Whisper («Субтитры сделал DimaTorzok», «Продолжение следует…»).

## 5. Скользящий буфер и оценка «интересности»

**TranscriptBuffer** — список `Line(ts, seq, speaker, text, is_bot)`, ограничен по времени
(`BUFFER_WINDOW_S`, 3 мин) и по количеству (`BUFFER_MAX_LINES`). Реплики бота тоже кладутся
в буфер, чтобы LLM видела, что бот уже сказал.

Логика обработки каждой фразы:

1. **Стоп-слово** («стоп», «хватит») при говорящем боте → `vc.stop()`.
2. **Wake word** (точное совпадение для коротких слов, fuzzy ≥85 для длинных; ё→е).
   - Если после имени есть вопрос → прямой ответ.
   - Если только «Сёма!» → открываем **окно внимания** на 8 с для этого человека:
     его следующая фраза считается обращением к боту.
3. Иначе — **префильтр**: очки за ключевые слова тем (до 2 на тему), +3 за запрос мнения
   («как думаешь», «кто прав»), +1.5 за маркеры спора, +0.5 за вопрос. Очки накапливаются
   и сгорают через 60 с.
4. Если сумма ≥ `PREFILTER_THRESHOLD` **или** бот говорил меньше `FOLLOW_UP_WINDOW_S` назад
   (люди могут отвечать ему без имени) — запускаем **отложенную оценку**:
   - ждём паузу в разговоре (`QUIET_GAP_S`, все молчат) — вклиниваться можно только в паузу;
   - проверяем `SpeakPolicy` (кулдаун 2 мин, ≤4 инициатив за 10 мин, бюджет классификатора в час);
   - LLM-классификатор получает последние 20 реплик и возвращает JSON
     `{addressed_to_bot, intervene, confidence, topic, angle, reason}`;
   - `addressed_to_bot` → отвечаем как на прямое обращение;
   - `intervene && confidence ≥ 0.7` → генерируем реплику, ещё раз проверяем тишину,
     говорим.

Промпт классификатора явно просит быть **консервативным**: пропущенный момент дешевле
надоевшего бота.

## 6. Отправка голоса в Discord

- TTS `gpt-4o-mini-tts`, `response_format="pcm"` → поток PCM s16le 24 кГц моно.
- `StreamingPCMSource(discord.AudioSource)` — буфер, который наполняется чанками TTS;
  плеер discord.py вызывает `read()` каждые 20 мс и получает 3840 байт 48 кГц стерео.
  Конвертация — потоковый линейный апсемплинг ×2 с переносом последнего сэмпла (без щелчков
  на стыках). FFmpeg не нужен.
- Пока TTS не догнал — `read()` отдаёт тишину; `b""` только после `finish()` и опустошения
  буфера.
- Воспроизведение начинается с первого чанка → задержка «до первого звука» ≈ время LLM + ~300 мс.
- **Barge-in:** если во время *инициативной* реплики кто-то говорит дольше 500 мс — бот
  замолкает. Прямой ответ прерывается только стоп-словом или новым обращением.
- Эха нет: Discord не возвращает боту его собственный поток.

## 7. Стоимость

- Основной расход в фоне — STT всех фраз всех участников. Варианты:
  - `STT_BACKEND=local` — faster-whisper на GPU, фон бесплатный;
  - гибрид (TODO): фон локально, а фразу с wake word перераспознать через OpenAI для качества.
- LLM-классификатор: лимит в час + вызов только после префильтра.
- Автовыход, когда в канале не осталось людей.
- Команда `/proactive false` выключает инициативу полностью.

## 8. Дальнейшие улучшения

1. **Стриминг LLM → TTS по предложениям**: озвучивать первое предложение, пока генерируется
   второе (−1 с задержки).
2. **Realtime API для ответа** (text in → audio out) вместо LLM + TTS.
3. **Суммаризация** реплик, выпадающих из окна, в «долгую память» сессии дешёвой моделью.
4. **Silero VAD** вместо webrtcvad — меньше ложных срабатываний на клавиатуру и музыку.
5. Учёт расходов в рублях/долларах по токенам и минутам, дневной бюджет.
6. Персональные настройки на сервер (имя, темы, голос) в SQLite.

## 9. Риски и что проверить в первую очередь

- **E2EE голоса (DAVE).** Discord переводит голосовые каналы на сквозное шифрование. Убедитесь,
  что ваши версии `discord.py` и особенно `discord-ext-voice-recv` поддерживают DAVE на
  **приём** — иначе sink получит не декодируемые данные. Это первое, что стоит проверить
  минимальным прототипом «записать 10 секунд в WAV».
- Privileged intent **Server Members** нужно включить в Developer Portal.
- `webrtcvad` на Windows ставится пакетом `webrtcvad-wheels`.
- Названия моделей OpenAI меняются — вынесены в `.env`.
- Этика: предупредите участников, что бот слушает и отправляет речь в облако.
